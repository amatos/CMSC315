\section{Design}

The goal of the project was to understand graph terminology, and how to work with graphs in Java. The main challenge of this project was in tracking individual vertices, as well the edges, if any, connecting them.  This programmer's solution to the problem consisted of building upon the methods and techniques covered in previous weeks, using linked lists, queues, stacks, recursion, and other data structures.  As directed by the project requirements, the application consists of 4 main classes:

\begin{itemize}
  \item App: the main class that drives the application.
  \item Graph: the class that represents the graph and its vertices and edges.
  \item Vertex: the class that represents a vertex in the graph.
  \item GraphPane: the class that represents the graphical user interface for the graph, extending Pane.
\end{itemize}

The application makes use of JavaFX for the graphical user interface, is built via Maven, and uses JUnit for unit testing.

\section{Lessons Learned}
During the course of this project, this programmer further developed his skills in Java and JavaFX.  While there weren't any memorable challenges that came up, there were several points in where the programmer had to stop and consider the project requirements.  For example, while graphs that do not contain a vertex A is perfectly valid, the project requirements specifically identified that all graphs must start with Vertex A, and proceed through the remainder of the alphabet.  This also imposed a maximal limit on the number of vertices that could be used in the graph, i.e., no more than 26 vertices.

Regarding the requirement that the graph must begin with vertex A, there is a specific check in the unit tests that explicitly fail a connected graph that only contains a single vertex, B.  Please see line 13 of the following code snippet taken from \emph{GraphTest.java}\textsuperscript{\ref{sec:unittests}}:

\begin{lstlisting}[language=Java]
@Test
void isConnectedHandlesEmptyMissingAConnectedAndDisconnectedCases() {
  Graph empty = new Graph();
  // The graph should return true, since it is a connected graph.
  assertTrue(empty.isConnected());

  // Define a graph that does NOT contain A
  Graph noA = new Graph();
  // Add a vertex B to the graph.
  noA.addVertex(new Vertex(1, 1, "B"));
  // Even though a single vertex graph is, by definition, connected, this
  // graph should return that it is NOT connected,
  assertFalse(noA.isConnected());
}
\end{lstlisting}
As noted in the comments (lines 11 and 12), this unit test is explicitly verifying that a graph containing a single vertex, B, is not connected, even though, \emph{by convention}, a single vertex graph is connected.  Yet, the project requirements state that all graphs must start with vertex A, which this graph does not contain.  Therefore, per the project requirements, this graph is considered disconnected.
